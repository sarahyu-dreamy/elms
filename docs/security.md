# 보안 모델과 남아 있는 위험

## 전제

이 앱은 드리미 공유 Supabase 프로젝트 안의 `app_6` 스키마를 씁니다. 플랫폼 구조상:

- 테이블을 만들면 `anon` 역할에 CRUD 권한이 **자동으로** 부여됩니다.
- 콘솔에 테이블별 RLS 설정이 노출되지 않습니다. 앱 단독으로는 정책을 걸 수 없습니다.
- `service_role` 키는 제공되지 않습니다. 서버도 `anon` 키로 접근합니다.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` 는 브라우저 번들에 포함됩니다. 공개 값입니다.

**결론: DB 레벨 방어는 존재하지 않습니다.** 앱 서버가 유일한 방어선입니다.

## 그래서 지키는 규칙

1. **모든 쓰기는 `lib/db-write.ts` 의 `supabaseWrite` 로만 한다.**
   쓰기 경로를 한 파일로 좁혀 두면, 나중에 진짜 RLS 나 `service_role` 키가 생겼을 때
   그 파일만 바꾸면 전체가 따라옵니다.

2. **쓰기 직전에 반드시 `requireEditor()` 또는 `requireAdmin()` 을 호출한다.**
   Server Action 안에서 호출해야 하고, 클라이언트가 보낸 역할 값은 절대 믿지 않습니다.
   현재 모든 쓰기 액션(`app/admin/*/actions.ts`)이 첫 줄에서 이 가드를 통과합니다.

3. **역할은 매 요청 포탈 userinfo 로 확인한다.**
   쿠키에는 access token 만 두고 역할은 담지 않습니다. 쿠키를 위조해도 역할이 올라가지 않습니다.

4. **관리자는 `ADMIN_SUBS` allowlist 로 지정한다.**
   포탈 role 은 "교사 일반"까지만 구분하므로, 이 LMS 의 관리자 권한은 `sub` 대조로 정합니다.

5. **클라이언트 컴포넌트에서 민감 테이블을 직접 조회하지 않는다.**
   모든 조회는 서버 컴포넌트에서 합니다.

## 남아 있는 위험 (앱이 해결할 수 없음)

앱을 거치지 않고 anon 키로 Supabase REST 를 직접 호출하면 다음이 가능합니다.
셋 다 **코드로는 막을 수 없고** 플랫폼 관리자와의 협의가 필요합니다.

### 1. 콘텐츠 무단 수정·삭제

누구든 `lexical_items` 등에 insert/update/delete 를 보낼 수 있습니다.
콘텐츠는 복구 가능하고 학생 개인정보가 아니라, 마일스톤 1 에서는 감수하고 진행합니다.

### 2. 정답 노출 — 지금 당장 실질적인 문제

`questions.answer` 를 anon 키로 읽을 수 있습니다. **학생이 마음먹으면 모든 문항의 정답을
미리 볼 수 있습니다.** 평가 도구로서는 치명적입니다.

당장의 완화책:
- 문항을 실제 시험에 쓰기 전까지 `is_published = false` 로 둡니다. (읽기 자체는 여전히 가능하므로 완화일 뿐입니다)
- 성적에 반영되는 평가에는 이 문항 은행을 그대로 쓰지 않습니다.

진짜 해결책은 아래 셋 중 하나이며, 모두 플랫폼 협의가 필요합니다.
- `questions` 테이블에서 `anon` 의 SELECT 를 막고, 채점을 서버 라우트에서만 수행
- 정답을 별도 테이블로 분리하고 그 테이블만 `anon` 접근 차단
- `service_role` 키 제공

### 3. 학생 개인 데이터 (마일스톤 2)

`speaking_submissions`, `attempts` 등이 생기면 **모든 학생의 성적과 녹음을 anon 키로
전부 읽을 수 있게 됩니다.** 이건 감수할 수 있는 수준이 아닙니다.

**마일스톤 2 착수 전에 반드시 해결해야 합니다.** 관리자(pgm)와 협의할 요청 사항:

> `app_6` 스키마의 학생 데이터 테이블에 대해 `anon` 의 SELECT/UPDATE/DELETE 를 차단하고,
> 앱 서버만 접근할 수 있는 경로(`service_role` 키 또는 앱 전용 DB 역할)를 제공해 주세요.
> 대안으로, 서버에서만 아는 비밀값을 인자로 받는 `SECURITY DEFINER` 함수를 통해서만
> 읽고 쓰게 하는 방식도 가능합니다.

## 확인 체크리스트

새 기능을 붙일 때마다:

- [ ] 이 경로가 쓰기를 하는가? → `supabaseWrite` 를 쓰고 가드를 통과하는가
- [ ] 학생 개인 데이터를 다루는가? → 위 3번이 해결됐는가
- [ ] 클라이언트 컴포넌트가 DB 를 직접 조회하는가? → 서버로 옮긴다
- [ ] 정답·점수처럼 학생이 보면 안 되는 값을 응답에 담는가? → 서버에서 걸러 내보낸다
